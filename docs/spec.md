> 本文件是給開發者（含 Claude Code）的完整需求說明。所有開發都以本文件為準，需求有變動時先更新本文件。
> 本儲存庫是**公開的**，**任何人名、電話都不可以出現在程式碼、測試資料、文件或 commit 訊息中**。測試用明顯的假名（測試甲、王小明）。區名是公開資訊。

## 1. 一句話目標

宏教分壇的**第二階段**（見分壇行事曆 `docs/spec.md` 第 2 節）：**一套系統放很多區**，每區有自己的行事曆和報名頁，家人在自己的區報名；**分壇行事曆自動讀各區的活動和報名名單**（分壇是統計端，不直接收報名）。先開「測試區」試用，穩定後再開真的區；教全區之後再從原本的系統搬過來。

## 2. 名稱與網址（2026/10/13 確認）

- 系統名稱：**各區報名系統**；每區頁面標題顯示「教真區行事曆」這樣。
- 網站：`https://bailixiao.github.io/region-signup/`（GitHub Pages，公開儲存庫 `bailixiao/region-signup`）。
- 後端：Cloudflare Worker `region-signup-api`。
- 每區的網址：`https://bailixiao.github.io/region-signup/#/r/教真區`（家人把這個加到主畫面）。

## 3. 區

- 區由**分壇總管理者**在後台開設（名稱只能是分壇 16 區之一，或「測試區」）。
- **測試區**：給管理者試用，**家人們看不到**（首頁不列出），分壇行事曆也不讀。網址知道的人可以打開。
- 區的狀態：開放（家人看得到、分壇會讀）／測試（隱藏）。
- 教全區：在搬過來之前**不開**（教全區的家人照常用原本的系統，分壇行事曆照常讀原本的系統）。

## 4. 使用者與權限

| 角色 | 權限 |
|---|---|
| 家人們 | 看自己區的行事曆、報名（可一次幫多人報）、查我的報名（取消、改期）。不用登入 |
| 區管理者 | 自己區的：新增／修改／刪除活動、看名單、幫人報名、取消或改期任何人的報名、操作紀錄 |
| 分壇總管理者 | 開設區、設定區管理者密碼、把區設為開放或測試；也可以管理任何一區 |

- 分壇總管理者密碼：Worker secret `SUPER_PASSWORD`（由管理者自己用 `npx.cmd wrangler secret put SUPER_PASSWORD` 設定）。
- 區管理者密碼：分壇總管理者在後台輸入（只存加鹽雜湊）。**Claude 不經手任何真的密碼**。
- 登入：選帳號（分壇總管理者或某一區）＋密碼；通行碼 12 小時有效；連續輸錯 10 次暫停 15 分鐘（每個帳號分開算）。

## 5. 活動

| 欄位 | 說明 |
|---|---|
| category | 勤務／道務／教育（同教全區） |
| mode | 報名型／公告型（公告型不用報名，只公告） |
| name、start、end、startTime、endTime、location、note | 同分壇行事曆（最長 60 天） |
| positions | 了愿項目：[{ id, name, min, max }]，最多 10 個；報名型至少 1 個 |

- 「最少」留空：勤務預設 2 人（「最多」小於 2 時以最多為準）；道務、教育不算缺人。「最多」留空＝不限。
- 狀態的算法同教全區（缺 N 人／額滿／人數足・N 人／已報 N 人／公告）。
- 有人報名的了愿項目不能刪除；有報名的日期不能移出活動期間；有人報名的活動不能刪除（要先取消）。

## 5-1. 區活動與分壇分配的勤務（2026/10/13）

活動分兩種：
| 種類 | 誰新增、修改 | 存在哪裡 |
|---|---|---|
| **區活動**（區內的研究班、區中心打掃⋯） | 區管理者（分壇總管理者也可以） | 該區的 Durable Object |
| **分壇分配**（分壇派給這一區的勤務） | **只有分壇**，在**分壇行事曆**後台新增、修改（可以一次派給好幾區） | 分壇行事曆；本系統自動讀進來，**只存報名** |

- 本系統的前門讀分壇行事曆的公開 `getEvents`（只取 `source=local`、`kind=分壇分配`、單位是這一區的），快取 2 分鐘；活動代號前面加 `F-`。
- 分壇那筆有填了愿項目與名額就照用；沒填的預設一個項目「參加」、不限人數、不算缺人。
- 卡片、活動頁、後台列表都標「分壇分配」。區管理者對分壇分配的勤務**只管報名**（看名單、幫人報名、取消、改期），不能改內容、不能刪除；要改請分壇在分壇行事曆後台改，幾分鐘內各區跟著變。
- 本系統後台**不能新增分壇分配的勤務**（分壇總管理者也一樣），只有一份，不會重複。區後台的新增按鈕寫「＋ 新增區活動」。
- 分壇刪掉的勤務：本系統就不再顯示（已經有的報名留在資料裡，不再顯示）。
- 測試：分壇行事曆後台可以把勤務派給「測試區」（分壇行事曆上不顯示），用來試連動。

## 6. 報名規則（取教全區第 7 節最核心的部分）

1. 報名填名字，可一次加多人（最多 10 人），每人報同一個了愿項目、同一天（多天活動選一天或多天）。
2. **同一人同一天在同一個活動只能報一個了愿項目**；名字相近視為同一人（三個字以上先去掉第一個字，剩下的有連續兩個字相同；一個字的名字只比對完全相同；同一批也適用）。
3. 到「最多」就擋住，顯示「額滿」。
4. 一次報多人時，只要其中一人被擋，整批都不寫入，列出被擋的人與原因。
5. **活動當天（含）之後不能自己報名、取消、改期**（請聯絡區管理者）；區管理者不受限制，名額與重複只警告。
6. **查我的報名**：輸入名字（完全相同才算，去掉前後空白），列出今天起的報名，可以取消、改期（改到同一個活動的其他日期，或換了愿項目）。名字放在 POST 內容，不放網址。
7. 報名、取消、改期都寫入該區的操作紀錄。
8. 第一版不做：成員名單與名字提示、道親／壇辦身分、陪同、還原。

## 7. 技術架構

| 層 | 技術 |
|---|---|
| 前端 | 單一 HTML/CSS/JS，GitHub Pages，手機優先、可加到主畫面（同分壇行事曆的風格） |
| 後端 | Cloudflare Worker ＋ Durable Object（SQLite） |

- **每區一個 Durable Object**（`idFromName(區名)`），各區資料分開存、分開排隊，一區很忙不會拖慢其他區。
- 另有一個 **registry** Durable Object：區清單、帳號（密碼雜湊）、登入通行碼、登入失敗次數。
- 前門 Worker：讀取有記憶體快取（區清單 60 秒、各區活動 30 秒）；寫入（報名等）直接進該區的 Durable Object。管理動作先向 registry 驗證通行碼，再轉給該區。
- 時區一律台北時間。

## 8. API

讀取 GET、寫入 POST（JSON、標頭 text/plain）。回應 `{ ok, data | error }`。

家人們：
- `regions`：開放的區（不含測試區）。
- `getEvents&region&from&to`：該區活動（含每天的狀態、人數）。
- `getEvent&region&id`：一個活動（含每天的名單：只有名字）。
- POST `signup`（region、eventId、dates、positionId、names）、`mySignups`（region、name）、`cancel`（region、signupId）、`reschedule`（region、signupId、date、positionId）。

給分壇行事曆讀（公開）：
- `feed&from&to`：所有**開放**的區的活動、每天的狀態和名單（只有名字），最長 62 天；快取 2 分鐘。加 `test=1` 連「測試」狀態的區（含測試區）一起，給分壇行事曆測試連動用（分壇的報名統計頁網址加 `?test=1`）。

管理：
- POST `adminLogin`（account：「分壇總管理者」或區名、password）、`adminLogout`。
- 區：`adminEvents`（含分壇分配的）、`adminSaveEvent`、`adminDeleteEvent`（只能是區活動）、`adminRoster`、`adminSignup`（幫人報名）、`adminCancel`、`adminReschedule`、`adminLog`（都帶 region；區管理者只能管自己的區）。
- 分壇總管理者：`superRegions`、`superSaveRegion`（name、status、password 可空＝不改）。

## 9. 畫面

- **首頁** `#/`：列出開放的區，點進去；記住上次的區，下次直接進。
- **區行事曆** `#/r/<區名>`：年／月／週／近期（同分壇行事曆），卡片顯示狀態（缺人／額滿／已報）。
- **活動頁** `#/r/<區名>/e/<活動 id>?date=`：資訊、每天的名單、報名表（選日期、了愿項目，加名字，確認報名，成功後顯示結果）。公告型沒有報名表。
- **查我的報名** `#/r/<區名>/mine`。
- **管理後台** `#/admin`：登入（選帳號）→ 區管理者看自己的區：活動、新增／修改、名單（可取消、改期、幫人報名）、操作紀錄；分壇總管理者多一個「區」分頁：開設區、設密碼、開放／測試。
- 按鈕至少 44px、做成按鈕的樣子；頁首「A＋」放大字體。

## 10. 開發流程

- 每完成一段就 commit 並 push；`node --test` 全部通過才 commit。
- 本機預覽：`node tools/dev-server.js --mock`（資料放記憶體，總管理者密碼 `test-super`、測試區密碼 `test-pass`），`.claude/launch.json` 設 autoPort。
- 改了 js、css 後把 `index.html` 的 `?v=` 換新。Service Worker 快取名稱帶網站路徑，只清自己的。
